# NOVA 启动器接入规范

> 版本 1.1 · 适用于 NOVA Game Space 桌面版
> 目标读者：游戏开发者、发行方、整合脚本作者，以及为本启动器做打包/适配的人。

NOVA 是一个本地优先的 Windows 游戏启动器。它不依赖账号系统、不依赖商店后端，
也不会改动游戏文件。它只做四件事：

1. 记录「这款游戏在哪」——可执行文件、启动参数、工作目录。
2. 从你的素材生成封面、主视觉与配色。
3. 启动进程，并把这次会话的时长记进本地库。
4. 进程结束（或崩溃）后回到启动器并给出通知。

任何游戏都可以通过两种方式接入：**手动添加（零代码）** 和 **清单文件（推荐给发行方）**。
下面是完整规范。

---

## 1. 两种接入方式

| 方式 | 适用场景 | 需要改游戏吗 | 最小要求 |
|---|---|---|---|
| 手动添加 | 自己买的、没有清单的老游戏、绿色版 | 不需要 | 一个 `.exe` |
| 清单文件 | 发行方、批量适配、团队内部规范 | 不需要，只多一个 json | 一个 `.exe` + `nova-game.json` |

两者最终写入同一份本地库（`%LOCALAPPDATA%\NOVA Game Space\library.json`），
行为完全一致。清单文件只是把手动填表变成了一次性可分发的东西。

---

## 2. 手动添加流程

1. 按 `A`（或点右上角 `+`）打开「导入本机游戏」。
2. 选择「手动添加…」，填写：
   - **游戏程序**：主 `.exe`。如果游戏有独立的启动器，指向启动器。
   - **显示名称**：会转成大写作为字标，例如 `Elden Ring` → `ELDEN RING`。
   - **中文名**：可留空。留空时字标使用显示名称。
   - **字标文字**：可覆盖字标（适合已经设计好标题的游戏）。
   - **封面 / 主视觉图片**：留空则从 exe 图标自动生成一张带光晕的 16:9 主视觉。
   - **启动参数 / 工作目录**：多为空；参数示例 `-windowed`、`--lang=zh`。
3. 保存。NOVA 会裁切出 1920×1080 主视觉与 800×450 封面，并采样主色。

### 路径规则

- 可执行文件必须存在，否则保存会被拒绝。
- 工作目录留空 = exe 所在目录。游戏需要从自身目录读资源时必须留空。
- 相对路径不支持；一律使用绝对路径（清单文件里的相对路径会在首次导入时解析成绝对路径）。
- 支持中文、空格与长路径。程序内部按 UTF-8 处理，不依赖当前代码页。

## 3. 清单文件规范（推荐）

在游戏根目录放一个 `nova-game.json`。NOVA 提供 CLI 导入时读取它；
你也可以把它随游戏一起分发，让用户「拖进来就能用」。

### 3.1 最小可用清单

```json
{
  "schema": 1,
  "name": "Elden Ring",
  "exe": "Game\\eldenring.exe"
}
```

### 3.2 完整字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schema` | number | 是 | 固定 `1`。未知版本会被拒绝并提示。 |
| `name` | string | 是 | 英文/原文名。会成为大写字标。建议 ≤ 24 字符。 |
| `zh` | string | 否 | 中文名。与 `name` 相同时自动省略，避免重复显示。 |
| `logo` | string | 否 | 字标覆盖文本。用于「标题艺名」与显示名不同的情况。 |
| `exe` | string | 是 | 相对清单文件的 exe 路径。 |
| `args` | string | 否 | 启动参数。按 Windows 命令行规则整体传入。 |
| `workdir` | string | 否 | 相对清单文件的工作目录，默认 exe 目录。 |
| `genre` | string | 否 | 类型，用 `·` 分隔，例如 `暗黑奇幻·动作RPG`。 |
| `ageRating` | string | 否 | 例如 `12+`、`16+`、`全年龄`。默认 `全年龄`。 |
| `mode` | string | 否 | `单人`、`单机 / 在线` 等。默认 `单人`。 |
| `tagline` | string | 否 | 一句话介绍，显示在主视觉下方。建议 ≤ 40 字。 |
| `description` | string | 否 | 详情页正文。建议 80–200 字。 |
| `hero` | string | 否 | 16:9 主视觉图片（≥1920×1080，JPG/PNG/WebP）。 |
| `cover` | string | 否 | 竖版或方版封面。缺失时从 `hero` 裁切。 |
| `accent` | string | 否 | 主色 `#RRGGBB`。缺失时从图片自动采样。 |
| `accent2` | string | 否 | 副色，用于渐变终点。 |
| `steamAppId` | string | 否 | 有 Steam 版本时填写，可跳转商店页。 |
| `requiresLauncher` | bool | 否 | 为 `true` 时提示用户先登录对应平台。 |
| `launcherHint` | string | 否 | 配合上行，例如 `首次启动需登录 Epic 账号`。 |

### 3.3 完整示例

```json
{
  "schema": 1,
  "name": "Cobalt Hour",
  "zh": "钴蓝时刻",
  "exe": "bin/CobaltHour.exe",
  "args": "-dx11",
  "workdir": ".",
  "genre": "都市异能·叙事",
  "ageRating": "16+",
  "mode": "单人",
  "tagline": "在蓝调时刻，城市只对能听见信号的人敞开。",
  "description": "白昼的都市没有魔法。他只能在午夜与黎明之间穿行，收集散落在城市缝隙里的蓝色信号，拼出一段被所有人遗忘的真相。",
  "hero": "art/hero.jpg",
  "cover": "art/cover.jpg",
  "accent": "#6fc8ff",
  "accent2": "#2f6bff",
  "steamAppId": "1234560"
}
```

### 3.4 校验规则

NOVA 在导入时会拒绝以下清单，并给出明确原因：

- `schema` 不是 `1`。
- 缺少 `name` 或 `exe`。
- `exe` 解析后不存在。
- `hero` / `cover` 指向的文件不存在（此时**降级**使用 exe 图标，而不是失败）。
- 文件不是合法 UTF-8 JSON。

可以带 BOM；多余字段会被忽略，方便你以后扩展。

## 4. 素材规范

NOVA 的观感由封面驱动，所以素材质量直接决定最终效果。

### 4.1 主视觉（hero）

- 尺寸：**1920×1080** 或更高，16:9。
- 构图：主体偏右，左侧 40% 留给标题与按钮。
- 亮度：避免整张纯黑或纯白。程序会采样亮度、饱和度、暖度与边缘密度，
  这些值决定标题字体配方的选择。
- 不要在主视觉上烘焙 UI 文字（按钮、菜单），它们会被裁切。

### 4.2 封面（cover）

- 尺寸：800×450（16:9）。启动器里的所有缩略卡都是这个比例。
- 如果只有竖版海报，NOVA 会居中裁切；把主体放在中间偏上更安全。

### 4.3 色彩

- 不给 `accent` 时，程序从主视觉采样主色，并推导出按钮渐变、光晕与文字对比色。
- 想控制品牌色就显式给 `accent` 与 `accent2`，两者应属于同一色系但明度不同。
- 按钮文字颜色由程序按亮度自动选黑或白，**不要**在素材里预设按钮颜色。

### 4.4 图标

- 没有图片素材时，从 exe 提取图标生成主视觉。
- 图标最好是 256×256、透明背景、方形。NOVA 会给它加圆角与光晕。
- 32×32 的旧图标会被放大并明显模糊，尽量避免。

## 5. 启动与生命周期

### 5.1 启动

- NOVA 用 `ShellExecute` 启动 exe，工作目录按规范解析。
- 图标、启动参数原样传递；不会注入环境变量，也不会 hook 进程。
- 首次启动前会确认文件存在；文件被移动时尝试在原目录找回同名 exe。

### 5.2 会话计时

- 计时从「进程成功创建」开始，到「进程退出」结束，按实际经过时间计。
- 若游戏本身启动了子进程（如启动器 → 游戏），计时跟随**最初创建的进程**。
  这类游戏请让 `exe` 指向真正的游戏本体，或接受「启动器存活时长」作为统计口径。
- 退出码非 0 且运行时间 **少于 20 秒** 视为崩溃；更长的非 0 退出按正常结束记录。
- 计时结果立即写入本地库，不依赖云端。

### 5.3 通知

结束时会产生一条本地通知，包含：

- 游戏名
- 本次时长
- 是否崩溃

这些通知只保存在内存中，重启后清空。

## 6. 与平台启动器的关系

| 场景 | 建议 | 原因 |
|---|---|---|
| 游戏有自己的平台（Steam/Epic/Riot） | `exe` 指向平台启动器，或直接用 NOVA 的 Steam 库扫描 | 平台负责更新与 DRM |
| 游戏需要账号登录 | 在 `launcherHint` 说明 | 首次启动会走平台登录流程 |
| 游戏是纯绿色版 | `exe` 指向本体，`requiresLauncher` 不填 | 直接启动即可 |
| 游戏需要管理员权限 | 在清单的 `description` 里注明 | NOVA 以普通权限运行，不会自动提权 |

NOVA 不会绕过任何 DRM、不会修改游戏文件、不会替换 DLL。

---

## 7. 校验清单

发布前逐项确认：

- [ ] `nova-game.json` 是合法 UTF-8 JSON，`schema` 为 `1`。
- [ ] `exe` 与 `workdir` 存在，且在干净的机器上路径正确。
- [ ] 主视觉为 16:9，标题区不压在主体脸上。
- [ ] 中文名与英文名不同（否则会被自动去重，字标可能不如预期）。
- [ ] 不带 `accent` 时，自动采样的颜色能接受。
- [ ] 启动一次，确认计时开始；关闭游戏，确认计时结束。
- [ ] 在 1366×768 与 4K 各看一次主界面，标题不溢出。

## 8. 常见问题

**Q：游戏启动后 NOVA 窗口会挡住游戏吗？**
不会。NOVA 进入启动画面后，游戏进程获得焦点；NOVA 不置顶。

**Q：能同时启动多个游戏吗？**
可以，每个游戏独立会话。但同一款游戏不会重复启动。
正在运行时按启动键会打开管理面板，而不是再开一个进程。

**Q：卸载游戏会删除存档吗？**
不会。「从游戏库移除」只删除库记录与 NOVA 缓存的封面，不触碰游戏目录。

**Q：能在另一台电脑复用配置吗？**
把 `%LOCALAPPDATA%\NOVA Game Space\library.json` 与 `media\` 一起复制过去即可。
路径不同的话，逐个在管理面板里重新指定 exe。

**Q：支持中文路径与空格吗？**
支持。所有路径按 Unicode 处理。

**Q：我改了 exe 位置怎么办？**
在游戏详情的「管理」里重新选择程序即可，播放时长与收藏都会保留。
