# 沉浸模式 · 重新设计（v2）

> 触发：Owner 反馈「边框过长、没考虑手柄、整体不好看」，要求以资深前端 UI 设计师视角重做。
> 上一版（§1.19）是「一条 1280px 横板 + 底部图标条」，本期推倒这条横板，改为
> **两个短簇 + 一条游戏带**，并把焦点导航做成一等公民。

## 〇、触发条件（2026-11-10 修正）

**沉浸模式 = 菜单里的「沉稳模式」开关**，不是全屏。

| 用户操作 | 结果 |
| --- | --- |
| 按 `F` / 菜单「全屏显示」 | 只放大窗口：原来的无边框全屏页面，版式不变 |
| 打开「沉稳模式」 | 本文件描述的沉浸版式：全幅封面 + 双簇 + 底部游戏带 |
| 全屏 + 沉稳 | 两者叠加：无边框 + 沉浸版式 |

代码上唯一的开关是 `html.calm`（`state.settings.calm`）。全屏只是 `html.is-fullscreen`，
与版式无关。§1.20–§1.22 的实现曾把它挂在全屏上，导致按 `F` 就把玩家的正常页面
换成了另一套设计 —— 已按本节改正。


## 一、诊断（为什么上一版不好看、不好用）

1. **一条 1280px 的通栏板**：边框从屏幕左内边距拉到右内边距，视觉上是「工具栏」而不是
   主机界面；玩家的眼睛要横向扫 1200px 才能看完 7 个信息块，阅读动线被打断。
2. **拼贴感**：进度、缩放开关在横板里各自带底色（纸卡 / 暗井），叠在同一块板上像补丁。
3. **尺寸不合交互**：按钮 26px 高、图标 56px，拇指/摇杆选起来费劲；命中区域小于
   主机 UI 的 44–48px 下限。
4. **手柄只能靠快捷键**：A=启动、Y=详情、X=收藏，但**不能把焦点走到按钮上再按 A**；
   方向键在主页只做「换游戏」，无法进入操作区。键盘 Tab 的焦点环在深色封面上几乎看不见。
5. **没有导航层级**：横板（操作）与图标带（选游戏）之间没有上下关系，玩家不知道
   「往下走会去哪」。

## 二、新结构：两个簇 + 一条带

```
┌───────────────────────────────────────────────────────────┐
│  顶栏（不变，46px）                                        │
├───────────────────────────────────────────────────────────┤
│                                                           │
│                    游戏封面（全幅，主角）                  │
│                                                           │
│                                            ┌────────────┐ │
│  ▍ 系列标签（accent 短横 28px）             │ 本次游玩    │ │
│  大标题                                     │ 14.5 小时   │ │
│  一句简介（≤42 字，单行截断到两行）          │ ▁▁▁▁▁▁▁    │ │
│  动作 · 冒险 · 12+ · 单人                   ├────────────┤ │
│  ┌──────────────┐ ┌────────┐ ┌────────┐    │ ◻ 开启缩放  │ │
│  │  ▶ 继续游戏  │ │ 详情   │ │ 缩放   │    │ 全屏·默认   │ │
│  └──────────────┘ └────────┘ └────────┘    └────────────┘ │
├───────────────────────────────────────────────────────────┤
│  ⌐图标¬ ⌐图标¬ ⌐图标¬ ⌐图标¬ ⌐图标¬ ⌐图标¬                │
│   名称   名称   名称   名称   名称   名称                  │
└───────────────────────────────────────────────────────────┘
```

- **左簇 identity**：无边框，文字直接压在底部压暗层上（content-as-UI）。最宽 560px。
- **右簇 status**：全界面**唯一保留边框**的卡片，宽 240–320px。游玩时长在上、缩放开关在下，
  两条边框融合成一张卡（中间一条发丝线），所以「最长边框」从 1280px 收到 ≤320px。
- **底部游戏带**：图标 64px、名称一行、整块可点（≥72px 高）；选中只给图标一条短底边
  （长度 = 图标宽），不再有整行下划线。

**为什么这样就不「边框过长」**：全屏里只剩两张卡（右簇一张，图标带各自的小方框），
其余靠排版与压暗分层。横向阅读距离从 1200px 降到约 560px。

## 三、视觉规则（14 套主题共用骨架，各自给材质）

| 元素 | 共享层规则 | 主题可改 |
| --- | --- | --- |
| 标题 | 字号 26–34px，行高 1.05，最多两行 | 字体、字距、大小写、是否有下划线 |
| 系列标签 | 前面一条 28×3px 的 accent 短横，8px 大字距 | 短横颜色/长度、是否改成小方框 |
| 简介 | 12–13px，最多两行，超长换行不截断 | 字体（衬线/等宽）、行高 |
| 主按钮 | 高 48px，圆角继承 `--hero-scale-radius`，字 14px | 底色/边框/圆角/大写 |
| 次按钮 | 高 44px，字 13px，图标 16px | 描边/是否只留图标 |
| 状态卡 | 背景/描边/圆角/墨色由 `--im-card-*` 给 | 纸卡、暗玻璃、硬偏移、虚线、双金线 |
| 缩放开关 | 高 44px，勾选形态由 `--hs-check-*` 给 | 形态 14 套各不相同（沿用上一轮） |
| 图标 | 64×64，圆角 8px，选中 2px accent + 短底边 | 圆角/描边/比例、选中态形状 |

## 四、焦点与手柄交互模型

### 4.1 两条聚焦行

```
row 0  actions : 继续游戏 → 详情 → 缩放设置 → 开启缩放
row 1  strip   : 游戏图标 1..n（横向滚动）
```

- `↑ / ↓`：在 actions 与 strip 之间切换。**actions 在下、strip 更下**，所以 ↓ 进入 strip，
  ↑ 回到 actions。这是物理位置，不是抽象层。
- `← / →`：
  - 焦点在 actions：在四个控件之间移动，到头回绕。
  - 焦点在 strip：**换游戏**（保留既有肌肉记忆），焦点跟着新卡片走。
- `Enter / A`：激活当前焦点。
- `Esc / B`：第一次退出沉浸模式（回到窗口布局），不会误触启动。
- `Tab`：按 DOM 顺序走，与手柄顺序一致。

### 4.2 焦点环（三种输入各自不同）

| 输入 | 视觉 |
| --- | --- |
| 手柄 | `outline: 3px #fff`（offset 3px）+ `box-shadow: 0 0 0 3px rgba(0,0,0,.88)` 黑领，元素轻微放大 1.02，`z-index` 抬高 |
| 键盘 | 同上（`:focus-visible`），但不放大 |
| 鼠标 | 不显示焦点环（`data-input="pointer"` 下禁用），只保留 hover |

双色是必须的：单色 accent 环在 accent 主按钮上等于没有（nova 粉环压粉按钮实测看不出），
单色白环在纸面主题的白按钮上等于没有。黑领 + 白环这两条带必有一条落在对比区。
两者不能都用 `box-shadow`（后写的会盖住先写的），所以一条用 shadow 贴边、一条用 outline 让位。

### 4.3 命中区域

- 主按钮 48px 高、最小宽 168px。
- 次按钮 44px 高、最小宽 96px。
- 缩放开关整行 44px 高、宽 100%（状态卡内）。
- 游戏图标 64×64，卡片整体可点（图标 + 名称 ≈ 92px 高）。
- 相邻可点元素间距 ≥ 10px，避免误触。

### 4.4 无障碍

- 焦点顺序 = 视觉顺序（左簇自上而下，然后右簇，最后图标带）。
- 每个控件保留 `aria-label`；缩放开关保持 `role="checkbox"` + `aria-checked`。
- 文字对比：14 套 × 14 个控件全部 ≥ 4.5:1（标题等大字 ≥ 3.0），见 4.5。

### 4.5 控件材质与墨色配对（第七条铁律）

**底与字必须同源。** 只改一半就是白底白字——这不是夸张，是实测：

| 主题 | 次按钮修复前 | 现在 |
| --- | --- | --- |
| grimoire | 1.01:1 | 13.9:1 |
| riot | 1.10:1 | 18.9:1 |
| riso | 1.11:1 | 19.0:1 |
| summer | 1.16:1 | 14.6:1 |
| broadcast | 1.05:1 | 9.4:1 |

**令牌分工**

| 令牌 | 管什么 | 谁给 |
| --- | --- | --- |
| `--im-ink` / `--im-ink-dim` | 压在封面上的主文字 / 次级文字 | 主题，默认浅色 |
| `--im-kicker-ink` / `--im-kicker-dim` | 眉标自带浅底时（dusk 丝带、summer 黄块、zerohour 青柠块） | 主题 |
| `--im-card-ink` / `--im-card-muted` | 右簇状态卡自成一套 | 主题（浅卡配深墨，深卡配浅墨） |
| `--im-cta-bg/-ink/-border/-shadow/-radius` | 主按钮整套材质 | 主题 |
| `--im-btn-bg/-ink/-border/-shadow/-radius` | 次按钮整套材质 | 主题 |
| `--im-cta-font/-size/-weight/-tracking/-transform`、`--im-btn-*` 同族 | 字体语言 | 主题 |
| `--im-body-font`、`--im-label-font`、`--im-num-font` | 正文 / 标签 / 数字 | 主题，缺省继承 |

**字体分工**：标题与按钮用 `--font-display`（宋体主题就是宋体），事实行、卡片副行、图标带名
一律 `--font-ui`。10px 宋体在米白纸上是灰糊不是墨——字号下限 11px、字重 500 是本轮实测结论。

**验收方式**：`node tools/immersive-audit.js`（双帧差分，196 个读数，失败退出码 1）。

## 五、验收标准

1. 全屏下最长连续边框 ≤ 320px（右簇卡片），左簇与图标带无通栏边框。
2. 键盘：`↑ ↓ ← →` 能在 actions / strip 之间完整走一圈，`Enter` 激活，`Esc` 退出。
3. 手柄：同一套路径可用，`A` 激活 `B` 返回；焦点环在手柄与键盘下都清晰可见，鼠标下不出现。
4. 所有可点元素 ≥ 44px；14 套主题下按钮文字不截断、不换行成两行。
5. `theme-slot-check --strict`、`feature-checks`、`tier-shots`、`headless-shots --views=all` 零新增警告。
6. 窗口模式零改动（`compare-*.jpg` 左列与 1.16.5 基线一致）。
7. `immersive-audit.js` 196/196 通过：任何控件的文字对比都 ≥ 4.5:1（大字 ≥ 3.0），
   且主按钮、次按钮、眉标、卡片副行没有任何一项靠降低不透明度来"做次级"。
8. **任何分辨率都不重叠**：`node tools/layout-fit.js` 在 1920×1080 / 1600×900 / 1440×900 /
   1366×768 / 1280×720 / 1080×600 六档、每档多主题下，行动行、状态卡、标题与底部图标带
   的交叠面积都是 0。测试会先把标题换成 `DNF-SEASON1-ACT0.3`、描述换成两行长句，
   所以量到的是真实长名场景而不是演示库的短名。
9. 图标带高度不写死：`app.js` 的 `syncDockHeight()` 用 `ResizeObserver` 量 `.dock`
   的实际盒子，写回 `--im-dock-h`，stage 用这个值做底部内边距。换主题、换窗口大小、
   名字从一行变三行、卡片从 6 张变 45 张，都在同一帧内重新分配空间。

## 六、落地时的调整（与初稿的差异）

- **新增了一层包裹 DOM**：`<div class="status-card">` 包住 `progress-block` 与
  `hero-scale`。初稿想纯靠 CSS 把两半拼成一张卡，但网格行距会让它们永远隔开；
  包裹层是唯一干净的做法。窗口模式用 `display: contents` 让它"不存在"，
  所以窗口布局零变化。数据层与业务 JS 未动。

## 七、不做的事

- 不改数据层；不新增视图；不引入第三方焦点库。
- 不做鼠标拖拽/滚轮特化；手柄与键盘优先。
- 不引入第三方焦点库；复用现有 `NovaFocus` 与 `NovaPad` 的 modality 机制。
