# 分享卡片设计基准（CARD DESIGN BASELINE）

> 本文档是分享卡片（相机键 → 三规格导出卡）的设计基准：每套主题的卡片必须
> 让人一眼认出「这是这套主题的东西」，参照物是 **该主题开场动画的最终画面**
> （Owner 设计，`src/intro.css` 是唯一权威来源）。本轮（§1.27）覆盖 12 套主题；
> `nova`（默认）与 `endfield`（终末地/明日方舟，刚按 endfield-ui 重做过）不在范围内。
> 规格与红线：`docs/THEME-INTERFACES.md` §16.5；几何与 DOM：`src/share-cards.css`。

## 0. 方法：怎么「向开场动画看齐」

1. **先读终帧，再写卡片。** 每套主题在 `src/intro.css` 有一个开场区块，其最终
   静止态（动画播完的画面）就是设计基准。从中提取四样东西：
   **色板**（精确 hex，直接复用）、**母题**（至少 2 个签名母题进卡片）、
   **字体家族**（`--font-display` 系）、**材质**（渐变 / 噪点 SVG / 边线做法，
   data-URI 纹理可原样拷贝）。
2. **三种规格各自独立构图**，不是同一张换配色：
   - `poster` 1600×900：封面为主视觉，巨型时长数字；
   - `dossier` 1200×1500：画框封面 + 资料页（含 4 项事实 + 21 格阶梯）；
   - `score` 1600×840：封面板 + 数据面板（190px 大数字）。
3. **封面图永远是主角**（.sc-art 是玩家游戏的真实封面），开场母题做框架、
   装饰、材质与文字处理——卡片是「把玩家封面裱进主题的仪式里」，不是重画开场。
4. **DOM 不可改**。全部构图在 `themes/<id>/interfaces.css` 的 CARD CHARACTER 块
   （选择器一律 `html[data-theme="<id>"] .share-card …` 前缀）。

## 3. summer「夏日轻程」终帧设计解析（Owner 原文，2026-11-11）

> 本节是 Owner 对 summer 开场终帧的专业拆解，是该主题卡片的设计宪法。卡片构图与
> 它冲突时，以本节为准。

**核心理念：数字时代的「理性夏日」**——避开椰林沙滩，用数字化、网格化、工程化的
视觉语言重构夏日；传达轻快、科技感、属于数字原住民的「轻」旅行体验。融合瑞士
国际主义排版（Swiss Style）、数字科技美学（Tech/Digital）与酸性设计（Acid Design）。

**元素拆解**：

1. **网格系统与蓝图感**：浅蓝细网格 + 对角线 + 圆弧线交织 = 工程图纸 / UI 界面的
   底层逻辑；四角裁剪标记（crop marks）与十字定位符（+）强化制图感。
2. **极致色彩对比**：黑白为基调（巨大黑色块承载白色英文，最强视觉重心）；
   **高饱和酸性黄**（竖线 + 中文标签，刺眼如夏日阳光，打破黑白沉闷）；
   **科技蓝**（辅助信息、线条、右下像素棋盘格，冷静理性）。
3. **排版层级**：巨大无衬线英文（白字黑底）绝对主导 → 黑字黄底中文第二层级；
   **中文黄色色块微微压住黑色英文色块的底边**（空间交叠，打破死板边界）；
   **等宽字体**用于 `// GUGUOVA · SUMMER ISSUE` 与数据行（代码/终端语境）。
4. **几何与抽象**：交织蓝色曲线打破网格僵硬（风的轨迹 / 夏日光谱）；右下像素
   棋盘格是数字/赛博元素，平衡左侧黑块重量。
5. **构图**：**非对称平衡**——左中部的厚重黑块由右侧留白、轻盈蓝弧、右下像素
   网格平衡；对角细蓝线引导视线流动。
6. **微排版**：日期行上方一根极其克制的蓝色短横线；**两侧荧光黄竖线像画框把
   元素约束在中心区，右侧那根比左侧更靠内，制造向内挤压的视觉势能**。

**卡片落地要点**：三规格共用这套语言（poster=期刊封面 / dossier=专题页 /
score=封底数据页）；封面照片作为期刊图版进入构图；时长巨数用黑块白字或黄块
黑字承载；里程碑与档案数据走科技蓝制表行。
## 2. 硬规则（违反任何一条即返工）

1. 只改 `themes/<id>/interfaces.css` 的 CARD CHARACTER 块（整块替换）+
   `themes/<id>/theme.json` version patch +1（铁律 41）。**不碰** `src/share-cards.css`、
   HTML、其它主题、其它插槽。
2. 画布固定：poster 1600×900 / dossier 1200×1500 / score 1600×840；**任何元素不得
   溢出画布**（`node tools/share-shots.js --themes=<id>` 的 overflow 必须为 0）。
3. 对比度：小字 ≥4.5:1、大数字 ≥3:1（相对它的**真实底色**，含渐变底取最深端算）。
   禁止用 `opacity` 压字色（铁律 29）——需要次级就用实色混合。
4. 三个变体各自构图；封面图（.sc-art）必须保留且是视觉主角之一；品牌行、标题、
   时长、21 格阶梯、档位、签名行全部在场且可读。
5. 长标题安全：标题允许换行（共享层已有 `overflow-wrap:anywhere`），排版按两行
   标题预留余量；dossier 的 4 项事实文本超长用省略号（共享层已有）。
6. 卡片要经得起截图发出去：构图完成度高（背景材质铺满、边缘处理干净）、
   装饰不压文字（铁律 1）。
7. **仪表类母题必须带读数**：刻度盘/尺标/信号条画出来就一定要有它对应的数字
   （频率、电平、时码），只画骨架会被读成测试图。（broadcast 曾只有尺标没有读数。）
8. **相邻色阶差不小于 ~18 级才算一条边**：机壳、边框、纸边这类「结构线」如果和
   底色同明度，等于没有画。zerohour 的 CRT 机壳曾用 `#0d0f11` 压 `#0a0b0c`，
   13px 的气口被读成「屏幕顶在警示带上」。
9. **纸面主题不能漏掉 `--sc-plate`**：共享层 poster 的 `.sc-score` 默认铺
   `rgba(10,13,19,.62)` 深色玻璃（为压住深封面而设）。14 套里 13 套都按自己的
   纸/墨重定义了，**summer 漏了**，白纸上直接糊出一块灰板（§1.29）。新主题开张先
   把这条变量写掉：纸面主题要么改成纸色，要么像夏天一样整块去掉底板改挂蓝规。

## 4. 落地经验（2026-11-11 收官复核补充）

**伪元素是稀缺资源，加装饰前先查占用**。共享 DOM 对所有主题固定
（`.sc-art/.sc-wash/.sc-deco/.sc-frame/.sc-top/.sc-sheet/.sc-id/.sc-score/.sc-foot`），
主题只能往伪元素里塞东西。broadcast 现状：

| 变体 | 已占用 | 剩可用 |
| --- | --- | --- |
| poster | `.sc-deco::before`=ON AIR、`.sc-deco::after`=尺标、`.sc-frame::after`=FM 读数、`.sc-sheet::before`=报眉、`.sc-sheet::after`=时码牌 | `.sc-id::before/after`、`.sc-score::before/after`、`.sc-foot::before/after` |
| dossier | `.sc-frame::after`=FM 读数、`.sc-deco::before/after`=ON AIR+尺标、`.sc-sheet::after`=CH 号底纹 | 同上 |
| score | `.sc-sheet::before`=尺标（覆盖共享的竖脊）、`.sc-sheet::after`=CH 号底纹、`.sc-id::before`=播出日志、`.sc-id::after`=FM 读数、`.sc-deco::before`=ON AIR | `.sc-score::*`、`.sc-foot::*` |

**绝对定位的坐标系别猜**：伪元素挂在 `.sc-id` 上时，因为 `.sc-id`/`.sc-main` 都是
`static`，坐标实际以 `.sc-sheet` 为参照（会跑位，量过才知道）。往卡片右上角加东西
先量 `.sc-no` 的盒子——页号码牌在那儿，很容易压掉文字（broadcast score 的 FM 读数
第一版就是这么被裁掉半句的）。

**复核旧待办要先量再改**：本轮两条待办（红点被栏线切开、里程碑文字浮条外）量完
发现根本不成立，省下两处无谓改动。像素比色 + 放大裁剪比肉眼可靠。
